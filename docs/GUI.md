# Avalonia GUI 使用与构建

GUI 包含 Setup、连接与路由、配置、诊断四页。当前真实后端仅支持 Windows x64；共享 C# 核心与 Avalonia 界面为后续 macOS 后端保留接口。macOS 尚不能用本项目 GUI 连接 VPN。

## 本机启动

构建完成后或解压 Windows 运行包后，双击项目根目录的 `HKU-VPN.exe`，直接打开窗口，不弹出 PowerShell 控制台。原有 `Gui.cmd` 仍可使用。配置沿用 `.local/config.json`，数据库仍由 KeePassXC 管理。GUI 以普通权限运行，安装、连接、刷新或清理路由时启动受限本机管道通信的管理员辅助进程；只读路由查询和诊断不提权。

预览界面而不读取私人配置或执行实际网络操作：

```powershell
.\Start-Gui.ps1 -Demo
# 或 Gui.cmd --demo
```

演示连接、路由和诊断均为模拟数据，不能用作实际 VPN 状态证明。同一项目目录只允许打开一个 GUI；已经打开时应使用现有窗口或托盘图标。

## 首次 Setup

1. 在 Setup 页检查依赖。缺失时点击“安装 / 修复依赖”，接受需要的系统权限提示；下载和提取仍校验固定 OpenConnect 版本的 hash 和签名。也可以选择已有的安装包。
2. 点击“打开 KeePassXC”，创建并保存数据库，按照 [README](../README.md#配置-keepassxc) 填写用户名、Portal 密码和 TOTP。
3. 点击“填写配置与路由”，在配置页填写 CLI、数据库、条目、网关、可选代理和至少一个固定路由或域名。直连时代理地址留空。
4. 点击“本地验证条目并保存”，在弹出的密码框输入数据库主密码。验证成功后保存本机配置；这个步骤不登录 VPN。

普通“校验并保存配置”只验证格式，不验证数据库密码或真实连接。第一次安装 .NET Runtime 必须在启动 GUI 前完成：引导脚本可用 winget 安装 .NET 10 Runtime；没有 winget 时手动安装，或使用自包含发布版本。源码包中不含编译后的 GUI，需要先构建。Windows 运行包已携带 .NET 运行时，无需单独安装 .NET；KeePassXC、OpenConnect 等 VPN 依赖仍通过 Setup 页面配置。

## 连接与路由

点击“连接 VPN”，接受 UAC 提权提示。无凭据 TLS/XML 检查通过后，GUI 请求一次数据库主密码，随后自动提交用户名、VPN 密码和 TOTP；自动 MFA 获取失败或配置手动 MFA 时，GUI 请求六位验证码。取消密码/MFA 对话框会取消本次连接并请求清理。

连接页列出固定目标、域名返回的真实 IPv4 和 VPN DNS。路由状态查询核对接口和下一跳，不能仅根据配置存在或状态文件成功文字判断安装。隧道建立和域名解析分别展示；已连接但域名查询失败时，可检查域名状态并点击“刷新 / 应用全部路由”。

在连接页选择 IPv4/CIDR 或完整域名，输入目标后点击“添加路由”。每条固定或域名路由提供“编辑”和“删除”；编辑后点击“保存修改”，或取消编辑。搜索框可按目标、前缀、状态和来源筛选。单个 IPv4 自动补为 /32，CIDR 自动规范为网络地址。不支持 IPv6、通配符或 `.hk` 后缀匹配。

已连接时修改立即保存并同步路由；未连接时保存，下次连接应用。认证和断开过程中暂停编辑。VPN DNS 自动维护，不提供手动增删改入口；同一个域名返回多个 IP 时，编辑或删除任一行会修改整个域名目标。固定和域名共享的前缀在仍被任一目标使用时保留。可删除全部目标，此时不安装目标路由，也不切换默认路由。

同步失败时配置已经保存，旧路由保留；表中会显示仍安装的旧目标，可排查后点击“刷新 / 应用全部路由”重试。配置页在连接期间锁定；网卡、认证、网关等连接参数断开后修改。

域名 IP 由校园 DNS 获取，但应用本身也必须访问同一个真实 IP。Clash Fake-IP、DoH 和公共 DNS 的配合要求见 [操作说明](OPERATIONS.md#clash-或浏览器-dns-的配合)。没有实现 TTL 定时刷新。

## 断开和退出

点击“断开 / 恢复清理”取消认证或停止隧道，清理本次路由。Windows 后端先向其自己创建的隐藏 OpenConnect 控制台发送正常退出信号，超时后才强制停止拥有的进程，并调用现有清理脚本；实际网关注销与路由恢复仍需真实连接验证。

连接期间点窗口关闭按钮会隐藏到托盘，VPN 保持运行。托盘菜单提供打开、断开和“退出并清理”。未连接时关闭窗口退出 GUI。清理失败时窗口保留错误信息，可以重试；原有 `Disconnect.cmd` 仍可用于遗留会话恢复。

GUI 崩溃或通信断开后，辅助进程请求取消连接并执行清理；操作系统强制终止或机器掉电仍可能留下状态。不要删除会话记录来伪装清理成功。后台域名查询尚未结束时可能需要等其返回后重试。详细清理边界见 [操作说明](OPERATIONS.md#断开连接)。

不要同时用另一份项目、命令行工具和 GUI 修改相同配置或管理同一 VPN；连接入口使用归属锁防止同项目重复启动。GUI 启动时不自动接管已有 CLI 会话；可以先通过原窗口正常断开，或明确使用恢复清理按钮。

## 诊断

“本机依赖与配置检查”检查文件和配置；“网络 / 网关检查”额外检查代理端口、网关 DNS 以及无凭据 TLS/XML 握手。不会自动提交用户名、密码或 MFA，也不会修改路由。

日志只显示控制过的操作结果，不包含网关原始认证输出。导出报告对账号、路径、域名、IPv4 和六位数字做脱敏；报告不包含配置、数据库或原始会话 JSON。诊断检查不能证明账号认证、目标访问或跨境性能正常。

如果连接时出现 `invalid after a value` 或 `BytePositionInLine`，先断开并退出旧 GUI，再更新并重新构建 GUI 与 `lib/GuiBridge.ps1`。Windows 脚本结果使用 UTF-8/Base64 帧传输，避免混入普通输出；新 GUI 会把无效结果报告为具体操作阶段的错误。不要用删除本机配置或会话记录的方法处理解析错误。

代理端口超时不代表网关认证失败。如果 Clash 仅允许 IPv6 回环接入，`http://127.0.0.1:7890` 可能超时，而 `http://[::1]:7890` 可用。先测试实际监听地址再修改代理 URL；GUI、诊断和 CLI 均支持 IPv6 字面地址，套接字检查使用不带方括号的主机名。直连时代理地址仍留空。

## 源码构建

在项目根目录安装 .NET 10 SDK 后运行：

```powershell
.\Build-Gui.ps1
```

发布文件位于 `.local/gui/`，项目根目录生成 `HKU-VPN.exe` 启动入口，默认依赖 .NET 10 Runtime。最终用户运行发布文件不需要 SDK。若需要携带运行时：

```powershell
.\Build-Gui.ps1 -SelfContained
```

开发时也可以运行：

```powershell
dotnet run --project gui/HkuVpn.App/HkuVpn.App.csproj -- --root .
```

不安装系统服务，不使用浏览器 UI，不持续轮询校园服务器。隐藏窗口暂停连接时长显示更新；路由变化监听本机会话文件，不自动重复解析域名。日志缓存上限 200 条。

Windows 默认使用软件渲染，减少本工具简单页面的渲染资源占用；其他平台的实际渲染和后端仍需分别验证。

## 测试与验证边界

```powershell
dotnet run --project gui/HkuVpn.Tests/HkuVpn.Tests.csproj -c Release -- .
.\tests\Test-GuiBridge.ps1
```

第一条运行配置与路由增删改查校验、模拟 CLI、真实本机管道身份/请求通信以及 Avalonia 无窗口页面测试（包括搜索、断开时编辑和模拟连接中的即时同步）；第二条在独立模拟目录验证 Windows 路由快照和 UTF-8。均不停止真实进程或修改真实路由。页面截图放在 `.local/gui-tests/`，不包含私人配置。

真实 UAC 提权体验、HKU 登录/MFA、校园 DNS、目标访问、正常断开信号和新机器安装仍需用户在实际环境验证。macOS 后端和安装包尚未实现。

隐藏演示窗口的资源采样（预热 5 秒后采样约 60 秒，无真实 VPN 或辅助进程）：

```powershell
.\.local\gui\HkuVpn.exe --root . --profile-demo
```

结果保存在 `.local/gui-tests/profile.json`，只含模式和数值。该隐藏演示采样不代表真实连接时 GUI + 辅助进程 + OpenConnect 的总占用，也不代替可见窗口、托盘和真实网络负载的测试。

2026-10-13 的本机首版采样：软件渲染、预热 5 秒、隐藏演示窗口采样 60 秒，私有内存约 18–21 MiB、工作集约 71–72 MiB，CPU 约为单个核心的 1.3%。私有内存低于计划的 80 MiB 目标；空闲 CPU 尚未达到低于 1% 的目标。这是单次本机结果，不保证其他电脑或实际 VPN 连接时的表现。

## Windows EXE 运行包

```powershell
.\Package-Gui.ps1
```

生成项目目录旁的 `hku-vpn-windows-x64.zip`，包含根目录 `HKU-VPN.exe`、GUI、自带 .NET 运行时、脚本、模板及依赖许可。解压整个 ZIP 到可写目录后双击 EXE，在 Setup 页面配置环境和 KeePassXC。运行包不带账号、数据库、本机配置、现有 VPN 依赖和日志，适合分享。

启动入口会按自身位置定位程序，支持路径中的空格和中文，不依赖快捷方式的工作目录。可用 `HKU-VPN.exe --demo` 预览。请保留整个目录，不能只复制启动 EXE；当前不是单文件安装程序。运行包面向 Windows x64，启动器使用 Windows 自带 .NET Framework；macOS 尚未支持。首次配置与真实 VPN 登录仍须在目标电脑验证。

`Package-Gui.ps1 -NoBuild` 可打包现有 `.local/gui-package/` 自包含构建；默认打包会重新构建。发布步骤下载固定版本 Avalonia 的许可文本，并保留运行时与 NuGet 包中的第三方许可。源码 ZIP 仍使用 `Export-Source.ps1`，不包含这些编译文件。
运行包回归测试（只启动独立解压目录中的演示程序，不连接 VPN）：

```powershell
.\tests\Test-Package.ps1
```

检查运行包中没有本机配置、数据库、调试文件或本机路径，并在中文和空格路径、无关工作目录下启动 EXE，核对实际加载随包 .NET。发布脚本完整重编译并映射源码路径，防止旧 DLL 的调试路径暴露构建电脑信息。
