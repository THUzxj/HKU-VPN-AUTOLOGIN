# Avalonia GUI 与跨平台核心实现计划

状态：首版 Avalonia 四页界面、跨平台核心和 Windows 后端已实现，构建及离线测试已通过；真实 HKU 连接、UAC 体验和新机器安装尚待实测。macOS 后端未实现。连接页面同时呈现路由，现有 Windows 命令行入口保留。使用方法见 [GUI 使用说明](GUI.md)。

当前实现采用代码构造 Avalonia 控件；配置、认证和协议模型在共享核心，系统操作在 Windows 项目。后续可将界面编排进一步拆为 ViewModel，macOS 后端仍须独立实现，不以 Windows 构建成功作为 macOS 可用证明。

## 技术选择与范围

- C#、Avalonia、.NET 10。界面与共享核心不使用 Windows 专用目标框架；第一版交付 Windows x64，预留后续 macOS Apple Silicon 和 Intel 后端。Windows 采用依赖框架发布，由启动脚本检查 .NET Runtime，不依赖 Windows Desktop Runtime；最终用户不需要 SDK，开发与构建需要 SDK。
- GUI 使用 Avalonia 原生控件；首版界面编排位于 MainWindow，后续拆分 ViewModel，不加载浏览器或 WebView。OpenConnect CLI 继续负责 VPN 协议，KeePassXC CLI 继续提供用户名、密码和 TOTP。
- 共享 C# 核心负责配置模型和通用校验、CLI 参数与 stdin/stdout 交互、认证状态机、超时/取消、日志脱敏和路由展示模型。系统操作通过平台接口提供，不能在共享核心中直接调用 Windows 命令或假定盘符、网卡名称、路径大小写和接口索引格式。
- Windows 后端先复用现有 PowerShell 的依赖安装、域名路由和清理逻辑；新增非交互接口，保留 CLI 默认行为。配置校验逐步集中到共享核心，保留 PowerShell 兼容入口，并通过一致性测试防止两套规则分歧。
- macOS 后端不依赖 PowerShell；未来用平台模块和必要的小型 shell 脚本实现提权、隧道、路由、DNS 与依赖检测。macOS 安装包、签名、公证和真实连接验证不属于本轮 Windows 交付。
- 中文界面，支持键盘操作、窗口缩放与高 DPI。第一版不做自动连接、开机启动、多 VPN 并行连接、IPv6 或按 `.hk` 后缀自动匹配。

## 页面设计

四个页面首先接入模拟后端，布局、交互和状态展示不依赖 Windows 实现。平台能力决定具体依赖项、诊断项和可用操作，不能在未实现的平台显示虚假的安装或连接成功。

### Setup

首次运行且没有有效配置时默认打开此页；已配置用户仍可重新检查依赖。

按步骤完成：环境检查 → 安装缺失依赖 → KeePassXC 配置指引 → 参数与路由填写 → 本地凭据验证 → 保存配置。

- 显示 .NET Runtime 与平台后端提供的依赖检测结果。Windows 第一版检查 PowerShell、KeePassXC CLI、7-Zip、OpenConnect/Wintun；7-Zip 只在需要提取安装包时必需。其他平台不显示 Windows 专用依赖。
- 保留下载代理、使用已下载安装包、重试失败步骤的能力。下载和提取沿用已有固定 hash 与签名验证。
- 提供打开 KeePassXC、选择数据库/密钥文件、填写条目路径的按钮。微软 TOTP 注册仍由用户在浏览器完成；GUI 不接收二维码或长期 TOTP 密钥。
- 用密码框输入数据库主密码，在本机验证条目可读，随后清除输入框。setup 不尝试登录 VPN、不添加路由。
- 安装失败、取消提权、验证失败时显示具体阶段；不会覆盖已验证的旧配置。首次 .NET 运行时缺失时，由 GUI 启动前的引导脚本处理，不能依赖尚无法启动的界面安装自身运行时。

验收：在模拟依赖环境可完成首次配置和重复 setup；失败重试不丢旧配置；GUI 操作不要求用户切换到终端输入参数或密码。

### 连接与路由

顶部显示连接状态、当前网关、连接时长和连接/取消/断开按钮；中间显示路由表，底部显示本次操作结果。

| 路由列 | 内容 |
|---|---|
| 来源 | 固定 IPv4/CIDR、域名解析或 VPN DNS |
| 目标 | 配置的域名或地址 |
| 实际 IP/前缀 | 每个 DNS 返回地址单独一行 |
| 状态 | 未应用、解析中、已安装、已存在、冲突、失败、已移除 |
| 详情 | 查询时间、返回 TTL、失败原因；TTL 不代表自动刷新倒计时 |

- 连接时在 GUI 内请求数据库主密码；自动 MFA 失败或配置手动 MFA 时，在 GUI 中提供隐藏输入框。
- 固定路由和域名路由可同时展示。配置列表、DNS 解析结果和当前系统路由分别获取，再合并显示，不能把配置存在或状态文件成功文字等同于真实路由已安装。
- 支持本项目固定 IPv4/CIDR 和精确域名的添加、编辑、删除与搜索；连接中保存后立即同步，断开时下次连接应用。VPN DNS 自动维护。更新失败明确展示配置已保存、旧路由保留及待清理目标，可刷新重试。
- 隧道状态与路由状态分开：可显示“VPN 已连接，部分域名解析失败”。默认网关和全局 DNS 保持现有逻辑。
- 默认关闭窗口时最小化到托盘，界面明确提示此行为；菜单“退出”在连接中执行断开和清理，失败时保留恢复操作入口。取消登录也必须处理已经启动的子进程。

验收：模拟分段 MFA 提示、多 IP 解析、查询失败、路由冲突、取消连接、重复断开；路由表展示与模拟系统状态一致；其他 VPN 进程和非本次路由不受影响。

### 配置

- KeePassXC：CLI、数据库、密钥文件、凭据条目、TOTP 条目和自动 MFA 开关。
- VPN：网关列表、代理开关及地址、网卡名、MTU、TLS 兼容参数；高级字段默认折叠。
- 路由：固定 IPv4/CIDR、精确域名、校园 DNS。与连接页共用同一配置模型，不保存两份不同的目标列表。
- 保存前调用统一校验；写入采用同目录临时文件和原子替换，避免保存中断留下半份 JSON。旧配置缺少可选字段仍可加载。
- 连接中不允许改动影响进程归属的运行库路径、网卡名等字段；网关和认证配置在断开后修改。域名更新走独立操作，不能与断开或刷新同时执行。
- 不提供 VPN 密码、数据库主密码或 TOTP 密钥的持久化字段，不默认记住主密码。
- 逻辑参数（网关、代理、域名等）与本机参数（程序/数据库路径、运行库、网卡等）在模型中区分，现有 schemaVersion 1 配置继续兼容。复制 Windows 配置到 macOS 时必须重新检测和填写本机参数，不能将 Windows 绝对路径当成跨平台配置。

验收：配置往返不丢字段；无效输入阻止保存；保存失败保留旧配置；连接中的编辑范围和生效时机明确。

### 诊断

- 默认只读，分项检查依赖、配置、代理端口、网关 DNS/TLS、当前 VPN 网卡、目标实际路由和域名状态。
- 网络检查由用户主动点击，不定时探测服务器；不自动提交账号或 MFA。VPN 内 DNS 检查和路由刷新是不同操作，界面标明是否会添加路由。
- 日志显示时间、阶段、错误码与可读说明，限制缓存长度。敏感原始输出不直接显示或写入日志；认证 cookie、密码和验证码过滤后才进入 UI/日志事件流。
- 提供复制/导出脱敏报告；默认遮盖用户名、个人路径、内部地址和私人域名。报告不包含原始配置、数据库或会话 JSON。
- 路由修复入口复用断开/清理流程，并清楚区分只读检查与修改系统状态的操作。

验收：模拟故障能定位阶段；敏感值不会进入显示、日志或诊断导出；只读检查不修改路由、不发起认证。

## 架构与平台接口

| 模块 | 职责 | 平台边界 |
|---|---|---|
| `gui/HkuVpn.App` | Avalonia 四页、界面编排、交互与托盘入口 | 不直接调用系统路由或提权命令；托盘行为通过平台能力适配 |
| `gui/HkuVpn.Core` | 配置、认证/连接状态机、CLI 交互、路由展示模型和脱敏 | 不依赖 Avalonia、PowerShell 或 Windows API，可独立测试 |
| `gui/HkuVpn.Platform.Windows` | UAC、IPC、依赖安装、Wintun、系统路由/DNS 查询与清理 | 第一版真实平台后端，内部复用现有脚本 |
| `gui/HkuVpn.Platform.MacOS` | 后续 macOS 授权、依赖、隧道、路由/DNS 与清理 | 本轮只预留接口，不宣称 macOS 可用 |
| 测试模拟后端 | 模拟安装、认证、网络和路由结果 | 四页开发与跨平台核心验证不需要真实 VPN |

平台接口覆盖依赖检查/安装、权限提升与会话通信、隧道准备、系统路由/DNS 快照、添加/移除路由、进程身份验证与断开恢复。共享层使用稳定的会话 ID、路由归属记录和能力描述；Windows 接口索引仅作为后端内部信息。

依赖项、平台状态目录和启动方式由后端提供。Windows 继续兼容项目 `.local/`，后续 macOS 使用可写的本机应用数据目录，不能把配置写入签名后的 `.app` 包内。平台配置和会话记录不互相复制，域名解析结果与网络状态也不能跨机器复用。

## Windows 后端与权限

GUI 以普通权限运行，安装依赖、创建隧道和修改路由交给按需提权的辅助进程。VPN 连接期间需要保留其管理进程；断开后退出，不安装常驻系统服务。

UAC 提权启动不能直接按普通子进程方式重定向标准输入输出，因此 Windows 后端实现本机命名管道通信，而不是隐藏现有终端。管道限制当前用户/所需管理员身份访问，每次启动使用独立会话并验证对端身份。辅助进程只接受约定操作，不接受任意命令、脚本或 shell 字符串。跨平台核心仅定义通信契约；macOS 后续独立实现授权与本机 IPC，不照搬 UAC 或 Windows 管道 ACL。

通信分为结构化请求、进度、认证输入请求、路由结果、日志和最终结果，带请求 ID 与协议版本。密码只在受限 IPC 和 CLI 标准输入中短暂传递，不写入配置、命令行、临时文件或日志。所有后端遵循同一要求；Windows 的 C# 和 PowerShell 边界避免长期持有秘密。清除输入控件和缓冲区，并承认托管字符串无法保证即时物理抹除。

现有库需要增加：

1. 依赖检查与安装可分别调用，能上报阶段结果，不依赖 `Read-Host`。
2. 凭据验证接收内存输入，沿用 KeePassXC CLI 的超时和 stdin 处理。
3. 认证循环向 GUI 请求手动 MFA；不依赖 `Console.ReadKey`，支持取消和超时。
4. 路由查询返回结构化数据；现有会话记录继续作为归属依据，真实安装状态由系统查询确认。
5. 断开按会话身份执行，优先正常终止，超时后才使用已实现的进程筛选和强制清理。

状态机包含：未配置、就绪、准备连接、请求认证输入、连接中、已连接、断开中、需要恢复和失败。安装、连接、刷新及断开操作串行化，防止重复点击。GUI 崩溃或 IPC 断开时，辅助进程进入断开清理流程；硬终止留下的会话由下次启动检测，并提供明确恢复入口。

## 低占用策略与测量

- 无浏览器进程、无常驻 HTTP 服务、不内嵌 PowerShell 运行时。
- Avalonia 界面不使用持续动画或持续重绘，页面按需加载；性能结果不能直接沿用此前 WinForms 设想，必须测量 Avalonia 实现。
- UI 更新由事件驱动；路由表只在操作后和用户手动刷新时读取。连接时长用低频计时器，托盘隐藏时暂停非必要界面更新。
- 日志缓存限定条数/字节数，并批量更新控件；依赖检测结果缓存到本次操作结束，避免持续启动 CLI。
- GUI 之外，KeePassXC CLI 按需运行；域名刷新、诊断脚本完成后退出。连接辅助进程的内存单独报告，避免只测 GUI 隐藏后台成本。
- 原型测量启动时间、GUI 空闲/连接/托盘三种状态的 private bytes、工作集和 60 秒 CPU 时间，同时报告 GUI、辅助进程、OpenConnect 的总占用。区分首次启动和后续启动，不把磁盘包体当内存指标。
- 建议初始目标：GUI 独立稳态 private bytes 不超过 80 MiB；无操作时 CPU 平均低于单核的 1%。这是待实测的工程预算，不是现有性能结论；若超出，先定位成本再决定调整实现或预算。

## 实现阶段

| 阶段 | 交付 | 通过条件 |
|---|---|---|
| 1. 跨平台核心 | 通用配置、认证状态机、CLI 交互、平台接口、事件协议、模拟后端 | 核心不依赖 Windows/Avalonia；旧配置兼容；超时、取消、脱敏和路由状态测试通过 |
| 2. Avalonia 四页 | setup、连接与路由、配置、诊断页面，接入模拟后端 | 模拟首次安装、MFA、路由刷新和故障可从 GUI 完成；操作无终端依赖 |
| 3. Windows 后端 | UAC/IPC、非交互脚本桥接、依赖安装、Wintun 和路由查询/修改 | GUI/helper 能交换进度和认证输入；身份核对、取消、断开恢复通过；原有 CLI 测试通过 |
| 4. Windows 集成 | 四页接入真实后端，完成 setup、认证、路由、配置和诊断 | 模拟全流程通过；隧道与路由状态独立展示；真实登录与 DNS 另行实测 |
| 5. Windows 发布 | 托盘、正常断开、超时清理、崩溃恢复、启动引导、发布文档与性能测量 | 取消 UAC、断开时刷新、异常退出可恢复；新机器安装与实际占用有记录 |
| 后续：macOS 后端 | 授权/IPC、依赖、隧道、系统路由/DNS、平台交互与 `.app` 发布 | 在真实 Apple Silicon/Intel Mac 上验证相应构建、安装、连接和断开；单独记录支持范围 |

阶段 1、2 先完成共享核心和 Avalonia 模拟流程。阶段 3 优先验证提权后通信、无终端认证交互以及可靠断开；这三项未通过前，不进入阶段 4 的完整真实连接集成。Windows 完成不等于 macOS 后端完成，不能仅根据共享界面可启动就宣称跨平台 VPN 可用。

拟按上述模块新增 `gui/` 源码项目、Windows GUI 启动/构建脚本、非交互桥接接口和对应测试。共享核心使用普通 .NET 测试项目；平台后端按平台分别构建和验证。构建中间文件与发布二进制进入忽略目录，源码导出白名单与文档同步维护。现有 `.local/config.json` 和数据库不被开发测试覆盖。

## 最终验收与边界

离线验证在独立测试副本进行，覆盖配置兼容、协议/IPC、假 CLI 认证、路由归属、故障恢复和日志脱敏。共享核心测试不得依赖 Windows 命令，Windows 特有的测试单独标记。人工界面验证覆盖窗口缩放、Tab 顺序、按钮禁用状态、托盘和 UAC 取消。

真实 HKU 登录需要用户在 GUI 中自行输入数据库主密码，验证连接、MFA、DNS、目标访问及断开后路由恢复；不以构建成功或模拟测试替代真实连接验证。新机器首次安装和下载仍需要独立验证。

macOS 后续验证还需覆盖本机授权、平台路由/DNS、菜单和托盘行为、Apple Silicon/Intel 运行库及安装包签名/公证流程，不能用 Windows 模拟测试代替。

实现验证记录见 [GUI 使用说明](GUI.md#测试与验证边界) 和 [测试说明](TESTING.md)。当前未创建提交或推送。
